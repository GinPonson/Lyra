# Lyra

自用资产账本与金融分析 App：Flutter 客户端连接单个 **Python / FastAPI** 服务，DuckDB 保存账本、会话和工具审计。

> 服务端实现是 [`server/`](server/README.md)（Python 3.12 + FastAPI），账本 schema **15**、客户端协议 **2**。TypeScript/Fastify 版已随迁移整体删除，只存在于 git 历史里；切换与回退步骤见[切流运行手册](docs/plans/lyra-cutover-runbook-20261013.md)。

## 当前架构

- **一个 Lyra 助手**：Genkit 负责模型调用与工具循环，调用服务端 18 个只读金融工具，包括 17 个账本工具和独立的行情参考估值工具。
- **独立登录页**：提供 Google、Linux.do、GitHub 三种入口；未配置的来源显示不可用。App 使用系统浏览器授权，服务端只接受各来源显式配置的所有者身份，三种方式访问同一份私有账本。
- **计算复用**：持仓、FIFO、已实现盈亏、风险和压力分析继续使用同一套金融代码，App 查询和助手共享数据口径。
- **界面切换行情源**：在「我的 → 行情与估值」为股票与标准美股期权分别选择主来源、备用来源或关闭，每次选择自动提交，服务端确认后立即应用并持久化。同一所有者的所有设备和 Genkit 共用选择；已实现 Alpaca、MarketData 适配器，密钥只在服务端，缺价不会中断账本。
- **Gmail 单独授权**：身份登录不申请 Gmail 读取权限；已有 Gmail 导入使用独立授权配置。

部署、模型配置、三种 OAuth 登录的申请与所有者设置及升级步骤见 **[Genkit 与多来源登录](docs/genkit-oauth.md)**。至少完整配置一种登录来源，其他来源可以整组省略。

VPS 的 Docker Compose、HTTPS 代理、备份与手机联调命令见 **[服务端部署](docs/deployment.md)**。容器启动时校验配置，不完整会直接退出，随后才打开并迁移数据库。

行情默认关闭。服务器配置完整凭据后，对应来源会在 App 中变为可选；在界面选择即可自动启用，无需额外保存或重启服务。操作方法、统一契约、参考价与期权乘数规则见 **[行情接入与换源](docs/market-data.md)**。当前显示的是现有持仓按各自报价时点计算的参考估值。

## 服务端开发

需要 Python 3.12+ 与 [uv](https://docs.astral.sh/uv/)。在 `server/` 下执行：

```bash
uv run pytest          # 测试
uv run ruff check .    # 错误类静态检查
```

按 [`deploy/server.env.example`](deploy/server.env.example) 提供环境变量
（`LYRA_DATABASE_PATH`、`LYRA_IMPORT_STAGING_DIR`、`LYRA_SECRET_MASTER_KEY`，以及至少
一组完整的登录配置），从 `server/` 启动：

```bash
uv run --python 3.12 lyra-serve
```

**没有独立的配置检查命令**：配置在启动时校验，不完整或形态不对就直接退出——不会带着
"看起来启用了但永远登不进去"的配置上线。部署前的构建与启动见[服务端部署](docs/deployment.md)。

默认监听 `127.0.0.1:3141`。正式访问通过 HTTPS 反向代理，代理须支持 `/v1/events` 的 WebSocket 升级。

Flutter 开发入口见 [移动端说明](apps/mobile/README.md)。最新验证状态见 [实现进度](docs/progress.md)。

## 第一次使用

1. 打开独立登录页，填写并检测服务端地址，选择已启用的 Google、Linux.do 或 GitHub，使用该来源获准的账号完成浏览器授权；返回 App 后进入工作台。
2. 在「我的 → 证券账户」添加账户，或使用总览中的创建入口。填写自定义名称和 Schwab 导出文件名中的账户标识，例如 `Individual_XXX276_...csv` 对应 `XXX276`。
3. 选择官方导出的 CSV 或 XLSX，检查目标账户与导入预览，再确认写入账本。也可以先选文件，再按提示创建账户并继续原文件的预览。
4. 查看持仓、交易与分析；需要 AI 解释时，按当前账户范围新建 Lyra 对话。
5. 需要参考行情时，在「我的 → 行情与估值」为股票、期权分别选择已配置的主来源和可选备用来源；每次选择自动提交，确认后刷新行情。

创建证券账户仅建立账本归属，不代表连接了券商或自动同步资产。第三方登录用于身份验证，证券账户用于整理交易。每种登录来源须分别设置所有者白名单；不会按相同邮箱或昵称自动合并身份，也不开放注册。

未登录时显示独立登录页；登录后，App 的四个主入口是「总览、股票、交易、我的」。「总览」和「股票」提供参考估值与报价明细；「我的」集中管理登录身份、证券账户、启动时隐藏金额、启动账户、涨跌配色、行情与估值及 App 版本信息。服务器地址由发布构建预设，普通用户无需填写或管理连接。金额隐私、启动账户和配色等偏好保存在本机，退出登录后保留；行情来源选择保存在服务端，对同一所有者的设备共用。模型配置、行情凭据、数据模式和请求预算仍由服务器管理。详细行为见[移动端说明](apps/mobile/README.md#我的与常用设置)。

## 旧版本升级

当前客户端协议为 **2**，数据库 schema 为 **15**。schema 15 为同一私有账本保存各登录来源的稳定身份，迁入已有 Google 所有者绑定，保留有效 OAuth 设备凭据、财务数据及行情选择；无需因本次迁移强制重新登录。独立登录页和新增入口需要使用更新后的 App。

schema 14 保存行情来源选择，不撤销 schema 13 已签发的 OAuth 设备凭据。若从 schema 12 或更早版本升级，schema 13 仍会撤销旧匿名配对凭据，需要使用已配置的登录方式重新授权。旧 CLI 会话保留内容与工具记录并归档，新建会话使用 Genkit。升级前停服并备份数据库；旧服务端不能直接打开已升级数据库。

`docs/plans/` 与进度表中的早期记录保留设计演变过程；涉及 MCP、多 CLI 和配对码的旧设计已被本次迁移替代。
